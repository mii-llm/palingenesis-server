# Single-A100 server verification · 2026-11-17

Server commit `636703d` ran 28 jobs over authenticated HTTP on one NVIDIA A100 80 GB PCIe. Across the 23 advertised operations, 21 returned success, one returned a diagnostic warning and one raised an SDK exception. The API reported the correct terminal state and exposed the SDK output in both nonzero-exit cases.

## Environment and method

The tests used the host's Python 3.12.11 training environment and its existing SDK checkout at `/dev/shm/pgs-echo`. Models came from the host cache. The server listened on loopback behind an SSH tunnel. Only the committed server package and its tests were transferred. Inputs and output paths were isolated in `/tmp/pgs-api-a100.XsCyd8` on the host.

All four integration tests passed with both the newer SDK checkout and the older installed SDK layout. The functional jobs below used the newer checkout. The HTTP client checked submission, polling, exit code, incremental byte offsets and end-of-log for each job. Separate HTTP checks verified 401 for a missing token, 404 for an unknown job, 422 for an invalid operation and the job-list page limit.

## Scope and retained evidence

These were short single-GPU functional checks. Distributed training, model quality, sustained throughput, vLLM serving, Harbor container execution, harness capture and surgery weight editing were outside the exercised paths. Harbor row export, harness profile listing and surgery margin measurement were exercised. Both student and teacher used local model assets. Autopilot used a randomly initialized two-layer model to keep the sweep bounded.

The temporary service and tunnel were stopped. GPU memory use returned to its pre-test reading of 1,511 MiB. Per-job SDK logs are in the remote scratch directory under `state/<job-id>.log`, alongside the SQLite job history. The two large throwaway OPD weight shards were removed after verification.
